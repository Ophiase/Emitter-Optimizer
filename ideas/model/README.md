# Model — where the project becomes interesting

**[sketch]** The engine optimizes whatever it is given. What it is given is
where the value, and the fun, is: a richer objective, a number of emitters
chosen rather than typed, physics that looks like a real deployment, and
baselines to prove the result is good.

- [objective.md](objective.md) — what `G` should mean.
- [emitter-count.md](emitter-count.md) — how many emitters, decided.
- [baselines.md](baselines.md) — the classical answers, on the same grid.
- [piecewise-linear.md](piecewise-linear.md) — the fast path of the original
  Future Development.
- [physics.md](physics.md) — anisotropy, path loss, noise floor, surfaces.
- [three-dimensional.md](three-dimensional.md) — a volume, a surface, a mesh.
- [manifolds.md](manifolds.md) — a metric, a periodic cell, a quotient.
- [sphere.md](sphere.md) — the first manifold, with a known answer.
- [constraints.md](constraints.md) — rigid bodies, torsions, lattice sites.
- [crystals.md](crystals.md) — a periodic cell, atoms as emitters.
- [urea.md](urea.md) — the atoms of a urea cell, found in their density.
- [circuits.md](circuits.md) — pairs, interference, layouts.
- [implicit-energy.md](implicit-energy.md) — a continuous field, sampled,
  instead of a voxel grid.

## The order

**[sketch]** Objective first, because every other file compares against it;
then the count, then the baselines, then the physics. An objective without a
baseline is an opinion.
